01 Problem Statement

Researchers, students, and academics frequently deal with large volumes of research papers that are time-consuming to read, analyze, and compare. Extracting key insights, identifying contributions, and comparing methodologies across multiple papers is a tedious manual process.

The Research Paper Assistant solves this by enabling users to:

  • Upload multiple PDF research papers into a personal library
  • Ask natural language questions and receive accurate, cited answers
  • Auto-generate summaries, key contributions, limitations, and future work
  • Compare two or more papers side-by-side on any topic or custom question

The system uses Retrieval-Augmented Generation (RAG) to ground every answer in actual paper content — preventing hallucination and ensuring every response is traceable to a specific paper and page number.

02 Architecture

The system follows a two-pipeline RAG architecture: an Ingestion Pipeline that processes uploaded PDFs into a vector store, and a Query Pipeline that retrieves relevant chunks and passes them alongside the user question to the LLM.

Data Flow

  1. User uploads PDFs via the Streamlit sidebar
  2. PyPDF extracts raw text page-by-page
  3. LangChain TextSplitter chunks text (1000 chars, 200 overlap)
  4. Sentence Transformers converts each chunk to an embedding vector
  5. ChromaDB stores vectors with paper name + page metadata
  6. User question is embedded; Top-5 similar chunks retrieved via cosine similarity
  7. Chunks injected into a structured system prompt alongside the question
  8. Groq API (openai/gpt-oss-120b) generates a cited answer
  9. Response displayed in Streamlit UI with source paper and page details

03 Prompt Design

Three distinct prompt strategies are implemented in prompts.py to ensure grounded, structured, and citable outputs:

3.1 — Conversational QA Prompt

Used in the Agent Chat tab. The system message enforces strict grounding:

You are a research paper assistant.

Answer the user's question using ONLY the research paper
context provided below.

Rules:
1. Do not use information outside the provided context.
2. Do not make up facts.
3. If the answer is not available, clearly say so.
4. Give a clear and concise answer.

Research Paper Context:
-----------------------
{context}
-----------------------

User Question: {question}

3.2 — Document Analysis Prompts

Four dedicated prompts for the Document Analysis tab, each with targeted retrieval:

TypeRetrieval KeywordsOutput Format
📄 Summaryabstract, method, results, conclusionProblem → Approach → Methodology → Results → Conclusion
🔑 Contributionsinnovations, novelty, improvementsContribution + why it matters (bullet list)
⚠️ Limitationsweaknesses, constraints, challengesLimitation + possible impact (bullet list)
🔮 Future Workfuture research, open problemsEach future direction explained clearly

3.3 — Paper Comparison Prompts

  • Custom Question Mode: Chunks retrieved per paper → LLM compares on the specific user question
  • Auto-Summary Mode: Structured comparison covering Research Problem, Approach, Key Results, Limitations, and an Overall Comparison for each selected paper

4.2 — RAG Quality

  • Retrieval: Top-5 chunks per query via cosine similarity — consistently on-topic
  • Grounding: System prompt restricts LLM to retrieved context only — no hallucination observed
  • Citations: Every response includes [Paper Name | Page X] references
  • Guard: min(n_results, available_chunks) prevents runtime errors on short papers
✅ Responses were manually spot-checked against source PDFs. The system consistently retrieved and cited the correct sections with high relevance.

06 Future Enhancements

  1. Persistent Cloud Storage — Integrate Pinecone or Qdrant for cross-session paper libraries
  2. Scientific Embeddings — Use allenai/scibert for better domain-specific retrieval
  3. Multi-modal Support — Extract and reason over figures, tables, and equations
  4. Citation Graph — Visualize cross-paper citation relationships interactively
  5. Export Reports — Download generated analysis as formatted PDF or Word document
  6. arXiv Integration — Auto-search and fetch papers by keyword from arXiv.org
  7. Collaborative Workspaces — Multi-user support for shared research teams
